# Marina — переносимые инструкции проекта

## Роли и среда

- VDS/Linux — основная среда разработки и тестов.
- Windows — Windows-specific и визуальная проверка.
- GitHub — единственная точка передачи между средами.
- Одновременно одну рабочую ветку изменяет только одна сторона.

## Безопасность

- Не добавляй в Git секреты, токены, `.env`, ключи и пользовательские данные.
- Не выполняй production deployment, публикацию, расходы, изменение доступов или удаление данных без явного подтверждения.
- Не используй `git reset --hard`, `git clean -fd*`, force push или автоматический rebase.
- Перед сменой среды выполни проверки, создай commit и отправь его в GitHub.
- Принимающая среда синхронизируется через `git fetch` и `git pull --ff-only`.

## Рабочий процесс

1. Прочитай `PROJECT.md`, `TASKS.md`, `STATE.md`.
2. Определи текущую задачу и её acceptance criteria.
3. Вноси минимальные изменения только в пределах задачи.
4. Проверь diff, тесты и отсутствие секретов.
5. Обнови `TASKS.md` и `STATE.md`, если изменились статус, риск или следующий шаг.

## Исполнители

- `luna_worker` — узкие механические задачи, документация и заранее определённые проверки.
- `terra_worker` — обычная реализация, отладка, интеграция и тесты.
- `sol_architect` — архитектура, безопасность, миграции, публичные контракты и независимый review.

Не запускай параллельных исполнителей с пересекающимися файлами.
